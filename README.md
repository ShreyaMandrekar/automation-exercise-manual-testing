# Automation Exercise – Manual Testing

## Project Overview

A practical manual software testing project based on the **Automation Exercise** web application.

The project demonstrates a complete QA workflow including application exploration, test planning, test scenario and test case design, manual test execution, defect reporting, retesting, regression testing, and API testing using Postman.

---

## Objective

The objective of this project is to gain practical experience in testing a real publicly available web application and to demonstrate the complete software testing lifecycle from requirement understanding and exploratory testing through defect validation and reporting.

## Testing Activities

### Manual UI Testing

The web application was explored and tested across major functional areas, including:

- Home page
- User registration / Signup
- Login and Logout
- Products
- Product search
- Product categories
- Product brands
- Product details
- Product reviews
- Shopping cart
- Checkout
- Contact Us
- Newsletter / Subscription
- Account deletion

Testing included functional validation, positive and negative test cases, boundary/validation checks, exploratory testing, retesting, and regression testing.

### API Testing

API testing was performed using **Postman** across 8 modules with 34 executed test cases.

The API testing covered:

- Products List
- Brands List
- Search Product
- User Login
- Create Account
- Delete Account
- Update Account
- User Details

The API tests included validation of:

- HTTP methods
- Request parameters
- Status codes
- API response codes
- Response messages
- Response structure
- Response data
- Positive and negative scenarios
- Unsupported HTTP methods
- Response-time observations

### Defect Testing

Defects were documented only when an actual reproducible issue was observed during testing.

The following UI defects were identified:

- Invalid zipcode accepted during account/address validation
- Invalid mobile number accepted during account/address validation
- Payment fields accepted invalid input formats

Each identified defect was documented with relevant test information and validated through retesting where applicable.
